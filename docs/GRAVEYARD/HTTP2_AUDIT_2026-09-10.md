## Verdict

For a vendor REST proxy, current H2 setup is optimal. gRPC/H3/WS correctly out of scope.

- Inbound: dual-ALPN `h2`+`http/1.1` via `node:http2 createSecureServer` (`src/index.ts:583-584`, `allowHTTP1: true`), cert-gated, `Bun.serve` H1 fallback without certs.
- Outbound: H2 pool (`src/network/h2_pool.ts`, 80 streams/session) + H2-first with H1 fallback (`src/network/fetcher.ts:565-590`). SSE over H2 with keep-alive. `/health` exposes `h2_outbound`.
- No gRPC/protobuf: fusion chains are in-process JSON; upstreams (OpenRouter/NVIDIA/Google/Zen) are REST-only.
- No HTTP/3 QUIC, no WebSockets — no lossy-edge or bidirectional use-case.

## Point-by-point conclusions

1. **Inbound H1 clients (OpenCode2/Claude Code)** — confirmed H1-only via Node `fetch`. No choice; dual-ALPN stays. H2 gain is upstream-only today.
2. **Per-key isolation (`origin#provider:keyIndex`, `fetcher.ts:413-416`)** — KEEP, but rationale is anti-429-pinning + quarantine/GOAWAY blast radius, NOT 500-teardown. A `500` is per-stream `:status`; stream closes via `attachStreamGuard`/`releaseStream`, session stays healthy. Purge only on session faults (`h2_pool.ts:272-280`).
3. **Inbound H1/H2 counter** — DEFERRED (user: avoid complications). CPU ~zero (`x-http-version` already set at `src/index.ts:616`), but `/health` schema + test churn for pure telemetry. Revisit only to prove H2 ratio.
4. **Upstream write backpressure asymmetry** — DEFERRED YAGNI. Downstream already waits on `drain` (`src/index.ts:516-518`); upstream `stream.write/end` doesn't (`fetcher.ts:532-535`). No speed gain; only memory-ceiling/tail-robustness under large-payload burst. Fix when RSS-under-burst proves need.
